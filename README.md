# edu-agent releases

Public orchestration for `shukezhinao/edu-agent` and `wonderl17/edu-agent`.
Application code, private build scripts and signing material stay outside this repository. Verified desktop installers are also available as public GitHub Release assets.

## Run a release

Open **Actions → Release → Run workflow**, select the private source repository and operation, and optionally enter a complete source commit SHA. Only commits in that repository's `main` history are accepted. Leave `confirm_release=no` for `verify`; select `yes` explicitly for `cloud`, `desktop` or `resume`.

`cloud` preserves the existing `all`, `web`, `api` and `worker` targets and migration options. `desktop` builds and signs the existing macOS/Windows packages once, mirrors their original bytes to R2 and publishes to the established COS and private GitHub Release destinations. The controller also copies the three verified installers to this repository’s `desktop-v<version>` Release. `resume` restores the original desktop packages without rebuilding and repeats this installer copy.

Every 15 minutes, **Check source versions** checks the canonical `shukezhinao/edu-agent` main branch. Increasing the root package version queues a cloud release; increasing the desktop package version queues a desktop release. `wonderl17/edu-agent` remains available as a manual source to avoid duplicate releases to the same Production environment. The migration baseline is `0.0.121`; existing versions are not republished. GitHub can delay scheduled runs.

Deployment metadata records attempted versions. Failed attempts require an explicit manual retry; they are not retried every poll. Scheduled releases and manual releases share concurrency groups, including desktop recovery. Disabling the `RELEASES_ENABLED` repository variable stops automatic and product release runs while allowing verification.

The separately gated `migration-bootstrap` operation prepares the explicitly authorized target project privately. It requires `MIGRATION_BOOTSTRAP_ENABLED=true`, `confirm_release=yes`, a full canonical source SHA, `target=all`, `run_migration=false` and no repair. The normal `RELEASES_ENABLED` switch can remain false. This operation shares the Cloud concurrency group and calls a separate private entry point; services remain IAM private, workers stay disabled, and it does not run ordinary Production checks or switch domains. `GCP_PRODUCTION_PROJECT_ID` selects the allowlisted project for WIF setup and read-only namespace verification. Workload configuration and all verification details remain private. All GCP operations (`cloud`, `verify` and `migration-bootstrap`) accept only `project-f1f104ee-36ad-451a-9b5`, which is also the workflow and controller default; an explicit retired source project is rejected before private credentials are requested. The two source repositories keep their former workflows disabled and expose the same non-secret `GCP_PRODUCTION_*` identity variables for consistent configuration; this does not grant those workflows access to the public-controller-only WIF trust.

Failed migration bootstrap runs may save a bounded, schema-validated metadata receipt under the fixed target's private Cloud Build bucket at `migration-diagnostics/<run-id>/<attempt>.log`. Only phase/status, tool exit codes and identity-match categories are eligible; raw private logs, arguments, credential fields, values and exception text are excluded. The local channel and upload file are mode 0600, cancellation skips diagnostics, and upload failure preserves the original result. Ordinary release operations do not use this channel. Public output remains fixed status messages; no Actions artifact or cache is created.

The explicitly authorized build-submit exception uses a separate controller-created 0600 channel, `MIGRATION_BOOTSTRAP_BUILD_ERROR`. Only a failed `gcloud` command in `build-api`, `build-worker` or `build-web` can upload its non-empty, at-most-8-KiB stderr channel. The controller revalidates the metadata receipt and exact regular-file path, then independently removes controls and redacts credential patterns, sensitive assignments and secret environment values. The bounded UTF-8 result goes only to the fixed private object `migration-diagnostics/<run-id>/<attempt>.build-submit.stderr.log`; `private.log` and arbitrary paths remain ineligible. External values of this channel variable are removed. Success and cancellation skip the upload, and public output contains only fixed status strings.

GitHub [disables public scheduled workflows after 60 days without repository activity](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule). After a successful poll, the scheduler uses this public repository's `GITHUB_TOKEN` to initialize `config/scheduler-activity.json` with the current UTC date, then updates that date through a normal maintenance commit only after at least 30 days. Future dates are preserved. This file contains only the maintenance date; no private source or secrets are committed. The check runs in this public repository on a standard runner and does not use private-repository minutes.

## Tencent validation

**Actions → Tencent validation** manages only the fixed Tencent validation host. `verify` checks access without building or deploying; `deploy` requires `confirm_release=yes` and an exact canonical `main` history commit (or resolves `main` once). It builds private source in isolated containers and uploads a checksum-bound package to a private, expiring COS relay using a one-hour presigned PUT URL. A dedicated forced-command SSH identity controls the release; the target downloads only its fixed ticket-bound object, captures a fresh recoverable snapshot, applies additive database migrations, and verifies the running API, workers and Web. Source and build logs are never published. Failure logs are bounded to 128 KiB and stay in a fixed root-only directory on the validation host; cancellation stops execution and skips diagnostic uploads.

Relay credentials remain on the target, restricted to its dedicated release prefix without list/delete permissions. The runner never receives COS access keys; URLs and response bodies are excluded from logs. Transfer tickets bind source, version, size and SHA-256, expire, and are consumed once. The private bucket uses managed encryption and one-day lifecycle expiry. The single-PUT transport refuses packages above 5 GiB instead of silently falling back to slow SSH payload streaming.

The separate `TENCENT_VALIDATION_ENABLED` and `TENCENT_VALIDATION_AUTOMATIC_ENABLED` environment variables gate manual deployment and scheduled version checks. Its baseline is `0.0.125`; failed scheduled versions require manual retry. An explicitly selected manual deployment may change the source SHA at the current version, guarded by the expected running SHA; downgrades are refused. This workflow shares only the existing App source-authentication environment and requests a read-only token for `shukezhinao/edu-agent`. It has no GCP/OIDC permissions, uses a separate concurrency group and non-production deployment metadata, and does not change Production DNS or services.

## Privacy and credentials

- A dedicated GitHub App is installed only on the two private source repositories. Read tokens fetch source; write tokens are issued only for private GitHub Release operations and expire automatically.
- Only the public controller is checked out by an Actions checkout step. Private source is fetched into a temporary directory and verified against its origin and trusted main history.
- Private stdout/stderr, exception messages and GitHub file commands never enter public logs, including failed commands. Public logs show fixed phases and status codes. Private temporary logs and source are removed after each run. Diagnose cloud failures in the private Cloud Build/Cloud Run consoles; public logs intentionally contain no build details.
- Desktop subprocess checkpoints add only fixed stage IDs and `start`/`success`/`failure` states after private execution. The trusted controller validates the latest 128 records from an 8 KiB private temporary channel, then removes it. Arguments, paths, environment values, child output and exception text are never included; diagnostic I/O failures do not change the release result. Product source and package metadata are unchanged.
- No Actions artifacts or Actions caches are uploaded. Existing COS, R2 and private GitHub Release uploads continue. Only `ShukeZhinao-<version>-mac-arm64.pkg`, `-mac-x64.pkg` and `-win-x64.exe` are copied from the selected private Release to this repository’s public Release; size and SHA-256 must match before and after upload. Source archives, logs, source maps, update packages and private release notes are excluded. Identical assets are reused; different bytes under the same name are rejected. Public tags target the controller commit, never the private source commit. The public write token stays outside private execution. A failed private publication remains failed even if its saved installers can be copied; cancellation stops the copy.
- GCP uses short-lived OIDC credentials restricted to this repository's main branch and exact release workflow. No GCP service-account key is stored here. Credentials are generated outside the private source upload directory.
- Production credentials live in the `production-release` environment, restricted to `main`. No PR-triggered privileged workflow exists. Official setup actions are pinned to immutable commits.

Changing trusted source code or this controller can change what it publishes. Keep repository write access limited and review workflow/script changes as production access changes.

## Checks

`python3 -m unittest discover -s scripts -p 'test_*.py' -v`

Tests include success/failure output sentinels, injected Actions commands, cancellation cleanup, trusted-source checks and scheduler de-duplication. `verify` checks live source access and configuration without building or deploying a product. Actual product publication is a separate explicitly confirmed operation.
